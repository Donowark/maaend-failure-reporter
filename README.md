# MaaEnd Failure Reporter

一个配合 MaaEnd「自定义程序」任务使用的 Windows 辅助工具。读取指定任务列表中的失败状态，将失败任务保存为桌面上的 TXT 文件，退出后由 MaaEnd 继续执行下一项任务。

这是独立的外部程序，无需修改 MaaEnd 安装文件，也不需要通过截图或 OCR 识别红色状态条。

## v0.3.1：等待任务结束后导出

如果 MaaEnd 启动导出器后，状态、配置和界面接口均已建立 TCP 连接却一直不响应，可把导出器放在列表最后一项，将「等待退出」设为关闭，并填写 `--instance "实际列表名" --after-run`。MaaEnd 可以先结束本轮队列，导出器在最多 100 秒内轮询实时状态。它要求列表停止运行且队列中的任务都有终态，等待期间检测到队列变化会生成异常报告。

在报告生成前保持 MaaEnd 开启，并避免启动同一列表的新一轮任务。由于接口没有提供启动导出器时的运行标识，程序只能从首次成功取得状态时开始跟踪该队列。如果需要在中间导出并等待报告写完再执行下一项，继续使用下方的即时导出设置。

此方式绕开 MaaEnd 同步等待导出器退出的路径。如果服务在任务结束后仍不响应，程序会生成异常报告。回归测试覆盖从短暂阻塞恢复、等待任务终态、检测队列变化及持续无响应。

## v0.3.0：解除配置接口对失败清单的阻断

- 优先读取本次 `/api/maa/state`，记录实际读取时间。
- `/api/config` 失败时，尝试新版 MXU 的 `/api/config/snapshot`；仍失败则使用名称缓存补全显示。
- 缓存仅含列表/任务 ID、名称和顺序，保存于 `%LOCALAPPDATA%\MaaEndFailureReporter\metadata-端口.json`，不保存运行状态或完整配置。使用缓存时报告明确标注时间及名称可能过时。
- 首次更新后，在 MaaEnd 空闲时运行一次 `Check.cmd` 建立名称缓存。没有缓存且配置不可用时，仍可通过 `--instance 列表ID` 导出失败任务 ID；不会猜测列表名。
- 实时状态读取失败时，始终生成异常报告；不会把上次运行状态当作本次结果。
- 诊断区分 TCP 建连、请求发送和响应首字节；状态失败时探测其他接口，帮助区分单接口异常与服务整体无响应。每次请求使用独立连接。
- 原有 10 秒超时、最多 3 次尝试及 100 秒整体期限继续生效。可选备用接口/翻译/诊断探测各最多尝试一次、3 秒。

本版通过模拟接口回归测试、竞态检测及 Windows x64 交叉编译，尚待 Windows 实机验证。此次报告只能确认三次请求均等待响应头超时；不能仅凭它认定 MXU 死锁。详见 [诊断依据与限制](docs/timeout-analysis.md)。

## v0.2.0：偶发接口超时处理

- 单次请求超时从 3 秒提高到 10 秒；遇到网络错误、超时或 HTTP 408/429/500/502/503/504 时，每个接口最多尝试 3 次，间隔 1 秒。
- 整体接口读取期限为 100 秒，包含三个接口及重试等待。正常响应时立即继续，不会固定等待 100 秒。
- HTTP 404、JSON 格式错误等不会反复重试。接口不兼容仍会明确报错。
- 成功、检查及异常报告均附请求次数、耗时和结果，便于确认重试是否恢复。
- 原有 MaaEnd 参数和开关配置保持适用。持续阻塞或 API 变化仍可能导致导出失败。

本版已通过模拟超时、重试恢复、持续失败、整体期限及状态筛选测试，并完成 Windows x64 交叉编译；v0.2.0 尚待 Windows 实机验证。下述 Win11 实测记录对应旧版。

## 功能

- 从 MXU 本机接口读取逐任务状态，筛选 `failed` 项。
- 覆盖滚动区域外的任务，不依赖窗口大小或列表是否可见。
- 按列表顺序记录失败任务的名称、位置与任务 ID；同名任务分别保留。
- 每次生成新的 TXT，文件名包含时间戳与随机编号，不覆盖已有报告。
- 自动获取 Windows 实际桌面路径，支持桌面迁移和 OneDrive 桌面。
- 读取异常时生成异常报告，避免误报为“没有失败任务”。

## 运行环境

- **操作系统：**Windows 11 x64。
- **MaaEnd：**需要所使用的 MXU 支持本机 Web 服务及逐任务状态接口。
- **运行依赖：**发布的 EXE 无需额外安装 Python、Go 或 .NET。

目前已由使用者在 **Windows 11、MaaEnd v2.31.0** 环境中确认可正常使用。其他版本尚未逐一验证；接口变化可能影响兼容性。

## 首次检查

1. 启动 MaaEnd，在设置中确认 **Web 服务**已启用，默认端口为 `12701`。修改相关设置后需重启 MaaEnd。仅本机使用时，无需开启“允许局域网访问”。
2. 先执行一次需要检查的任务列表，让它产生运行状态。
3. 双击 `Check.cmd`。
4. 查看桌面生成的 `MaaEnd_检查_*.txt`，确认目标列表的状态格式兼容，并记下它的名称或 ID。

检查报告成功保存到桌面，表示这次运行具备桌面写入权限。若无法写入桌面，程序会尝试保存到 `%LOCALAPPDATA%\MaaEndFailureReporter`；检查窗口会显示实际保存路径。

## 在 MaaEnd 中配置

将「自定义程序」任务放在所有需要统计的任务之后、后续操作之前。例如：

**日常游戏任务 → 失败任务导出器 → 结束游戏或其他任务**

| 设置项 | 配置 |
| --- | --- |
| 程序路径 | 通过右侧文件选择按钮，选择实际解压位置中的 `MaaEndFailureReporter.exe` |
| 附加参数 | `--instance "日常"`，将“日常”替换为实际任务列表标签名 |
| 等待退出 | 开启 |
| 已运行时跳过 | 关闭 |
| 通过 cmd 启动 | 关闭 |

**不要把 `Check.cmd` 填入自动任务的程序路径。**它是手动检查入口，会暂停等待按键。

程序路径必须指向真实存在的 EXE。压缩包可能包含一层子文件夹，请以实际解压位置为准，避免直接照抄示例路径。

多个列表同名时，使用检查报告中的列表 ID：

```text
--instance "列表ID"
```

如果修改过 Web 服务端口，还需指定端口：

```text
--instance "日常" --port 你的端口号
```

每个需要导出的任务列表应分别添加此程序，并指定对应名称或 ID。

## 输出内容

报告文件名示例：

```text
MaaEnd_失败任务_20261006_120000_123456789.txt
```

以下为报告内容示例，任务与统计数字仅用于演示：

```text
MaaEnd 失败任务清单
生成时间：2026-10-06 12:00:00 -0700
任务列表：日常
列表 ID：example
来源：MXU 本机任务状态接口

失败：2；成功：8；运行中：1；等待中：0
统计范围：调用时这个列表已登记的任务状态；尚未执行的后续任务不计入失败。

1. 转交委托
   列表位置：3；任务 ID：task-a
2. 基质刷取
   列表位置：7；任务 ID：task-b
```

文件采用 UTF-8 带 BOM 编码，可以用 Windows 记事本直接打开。

### 统计范围

- 只统计调用时指定列表当前登记的状态，不汇总历史运行。
- `pending`、`running`、`succeeded` 及未登记状态的任务不会被算作失败。
- 如果导出器后面还有任务，这些任务之后的执行结果不会出现在当前报告中。
- 当前没有失败项时，报告写明“当前状态中未发现失败任务”。没有登记状态时，会说明无法据此认定全部任务成功。

## 命令行参数

| 参数 | 说明 |
| --- | --- |
| `--instance "列表名或ID"` | 指定目标列表；建议在 MaaEnd 中始终填写 |
| `--after-run` | 等待指定列表结束后导出。需指定 `--instance`，并将导出器放在最后一项、关闭「等待退出」 |
| `--port 12701` | 指定 MXU 本机 Web 服务端口 |
| `--check` | 生成接口、任务列表与写入检查报告 |
| `--output-dir "D:/Reports"` | 保存到指定的、已存在的目录 |
| `--strict` | 检测或目标目录写入失败时返回非零退出码 |
| `--help` | 显示帮助 |

省略 `--instance` 时，程序会选择唯一运行中的列表；如果没有运行中的列表且配置仅含一个列表，则选择该列表。其他情况会提示明确指定列表。

默认情况下，导出异常也返回退出码 `0`，让调用方能够继续流程。使用 `--strict` 时，检测或目标目录写入失败返回 `1`；无效参数返回 `2`。后续任务是否继续最终由调用方决定。

## 故障排查

### MaaEnd 显示“自定义程序任务失败”，且没有报告

先确认程序路径正确。使用文件选择按钮重新选择 EXE；在命令提示符中运行同一路径，可以帮助判断程序是否成功启动。

如果提示 **“系统找不到指定的路径”**，应修正实际文件路径。

`Check.cmd` 可以运行，说明同目录中的 EXE 能在手动启动条件下运行；不代表 MaaEnd 中填写的路径也正确。

### 出现“导出异常”报告

查看报告中的具体原因，并检查：

- MaaEnd 是否已启动，Web 服务是否已启用。
- 实际服务端口是否与 `--port` 一致。
- `--instance` 是否准确匹配列表名称或 ID。
- 当前 MXU 是否提供兼容的逐任务状态接口。

### 找不到桌面报告

查看 `%LOCALAPPDATA%\MaaEndFailureReporter` 中是否存在备用报告。如果桌面和备用目录都不可写，程序无法保存文件。

### 反馈问题

提交 Issue 时，请提供 MaaEnd 和 MXU 版本、相关检查或异常报告，以及必要的任务状态截图。分享前请检查其中是否包含不希望公开的内容。

无需提供整个 `/api/config` 原始响应或完整 MaaEnd 配置文件，它们可能包含与问题无关的敏感配置。

## 从源码编译

安装 Go 1.22 或更高版本，在仓库根目录执行：

```bash
cd src
go test ./...
go build -buildvcs=false -trimpath -ldflags="-s -w" -o ../MaaEndFailureReporter.exe .
```

上述编译命令默认生成当前系统架构的程序；制作 Windows EXE 时应在 Windows 上编译，或设置相应的交叉编译环境。

项目使用 Go 标准库，测试覆盖失败项筛选、同名任务保留、列表选择、缺失或未知状态、只读接口调用及报告文件保存。

## 工作原理

程序仅向 `127.0.0.1` 上指定端口发送 GET 请求：

- `/api/config`：获取列表及任务名称。
- `/api/maa/state`：获取逐任务运行状态。
- `/api/interface`：获取任务显示名称与翻译；不可用时保留配置中的任务名。

它以启动程序的 Windows 用户身份保存报告，不修改 MaaEnd 配置，也不操作游戏。
